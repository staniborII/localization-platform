# Solution brief

Speech in an MP4 becomes English, German, and Spanish subtitle files. The video is not rewritten. A static site accepts the upload, a workflow transcribes and translates the speech, and other systems hear about the finished job from a queue.

You pay for each unit of work. Nothing in this design has a monthly fee for simply existing. A 5-minute clip is about $0.17 at the published example rates: $0.03 of Transcribe, $0.14 of Translate, and less than a cent for everything else. The MP4 sitting in the bucket is the other real number.

Frankfurt list prices are used where a decision record wrote them down. The other figures are the published examples in [How one video becomes subtitles](../understanding-the-pipeline.md), in the cost section at the end of that page, mostly US East. They show the unit. The longer path is that same page. The event fields are in [Events](../reference/events.md). The full limits are in [Trade-offs](trade-offs.md).

## From upload to the queue

- The browser hashes the MP4 and asks the presign Lambda (`presign`) for an upload URL, through CloudFront `POST /api/uploads`. The profile is the word after the last underscore in the file name.
- If that file was already uploaded, the presign Lambda returns the existing job and the browser does not upload again.
- Otherwise the browser uploads the MP4 straight to the S3 video upload bucket. S3 compares the SHA-256 of the bytes with the checksum on the signed URL. A match stores the object. A mismatch rejects the PUT, so no job starts.
- S3 publishes `Object Created` to the EventBridge default bus. The upload rule `IngressCreated` on that bus invokes the starter Lambda (`start-workflow-on-upload`). That function writes the job row in the DynamoDB job table and starts the Step Functions state machine (`workflow`).
- The state machine marks the job running. A file over 2 GB gets an audio-only copy from MediaConvert first. Amazon Transcribe then reads the media.
- The state machine invokes the token Lambda (`store-transcribe-task-token`), which stores a wait token generated by the state machine, and then pauses for up to four hours. It does not poll. The token is the handle for that pause. When Amazon Transcribe finishes, the resume Lambda (`transcribe-finished-callback`) sends that same token back with `SendTaskSuccess`, and that is what lets the state machine continue. 
- Amazon Transcribe publishes `Transcribe Job State Change` to the EventBridge default bus. The transcript rule `TranscriptReady` on that bus invokes the resume Lambda (`transcribe-finished-callback`), which wakes the state machine.
- The state machine invokes the subtitle Lambda (`write-translated-subtitles`). That function groups the words into cues, calls Amazon Translate for the lines that need it, and writes WebVTT and SRT for English, German, and Spanish to the S3 transcript and subtitle bucket.
- The state machine saves the finished status on the DynamoDB job row and publishes one event to the EventBridge application bus (`job-outcome-event-bus`): `LocalizationJobCompleted`, `LocalizationJobFailed`, `LocalizationJobNeedsReview`, or `LocalizationJobEmpty`.
- The fan-out rule `JobOutcomeFanoutRule` on that bus publishes the event to the SNS topic (`job-outcome-fanout-topic`). The topic delivers it to the SQS consumer queue (`job-outcome-inbox`). The message names the job and the subtitle keys. It does not include a download URL.

## Lambda

**Presign Lambda** (`presign`, web client stack)

- Does: checks the file name, hash, and size. Returns the existing job, or a 15-minute PUT URL.
- Triggered by: the browser, `POST /api/uploads`, through CloudFront.
- Triggers: nothing in AWS. The browser uploads the MP4.
- Costs: one Lambda request.

**Starter Lambda** (`start-workflow-on-upload`, pipeline stack)

- Does: writes the job row and the content lock, then starts one run. A bad profile, a missing checksum, or a file over 5 GB is stored as failed and does not start.
- Triggered by: the EventBridge upload rule `IngressCreated` on the default bus.
- Triggers: `StartExecution`, or nothing when the lock or the row already exists.
- Costs: one Lambda request, one DynamoDB write for the lock, and one for the job.

**Token Lambda** (`store-transcribe-task-token`, pipeline stack)

- Does: writes the wait token onto the job row. The token is the handle for the pause. The resume Lambda sends that same token back with `SendTaskSuccess` to let the state machine continue.
- Triggered by: the Step Functions state `WaitForTranscriptReady` in the state machine `workflow`.
- Triggers: nothing. The workflow stays paused.
- Costs: one Lambda request and one DynamoDB write.

**Resume Lambda** (`transcribe-finished-callback`, pipeline stack)

- Does: sends the transcript outcome back to the waiting run. A closed token is ignored.
- Triggered by: the EventBridge transcript rule `TranscriptReady` on the default bus.
- Triggers: `SendTaskSuccess`.
- Costs: one Lambda request and one DynamoDB read.

**Subtitle Lambda** (`write-translated-subtitles`, pipeline stack)

- Does: groups cues, translates what it must, and writes six files. It does not write `status`.
- Triggered by: the Step Functions state `BuildSubtitles` in the state machine `workflow`.
- Triggers: Translate, then the subtitle objects in S3.
- Costs: one Lambda request, plus one Translate charge per cue that is not already in the target language.

**Status Lambda** (`status`, web client stack)

- Does: lists jobs, reads one job, and signs 15-minute download links. It can also rerun a language, accept a mixed transcript, or continue a finished wait.
- Triggered by: the browser, `GET` or `POST /api/jobs`, through CloudFront.
- Triggers: a new execution, or `SendTaskSuccess`, only when the page asks for that.
- Costs: one Lambda request per poll. The detail page polls every 2 seconds while a job is `received` or `running`.

## EventBridge

**EventBridge default bus**

- Does: carries `Object Created` from the S3 video upload bucket and `Transcribe Job State Change` from Amazon Transcribe.
- Triggered by: S3 and Amazon Transcribe. This pipeline does not publish to it.
- Triggers: the upload rule `IngressCreated` and the transcript rule `TranscriptReady`.
- Costs: S3 `Object Created` is an opt-in data event. Transcribe job events are service events on this bus.

**Upload rule** `IngressCreated` (EventBridge rule on the default bus)

- Does: matches `Object Created` from the S3 video upload bucket for keys under `video-upload/`. The source is `aws.s3`.
- Triggered by: S3, after the MP4 PUT finishes, through the EventBridge default bus.
- Triggers: the starter Lambda `start-workflow-on-upload`. Two failed invokes send the event to the SQS upload dead-letter queue `upload-event-dead-letter`.
- Costs: included in the S3 event. The rule has no standing fee.

**Transcript rule** `TranscriptReady` (EventBridge rule on the default bus)

- Does: matches `Transcribe Job State Change` with status `COMPLETED` or `FAILED`. The source is `aws.transcribe`. It does not filter by job name. The resume Lambda does that.
- Triggered by: Amazon Transcribe, when a job finishes or fails, through the EventBridge default bus.
- Triggers: the resume Lambda `transcribe-finished-callback`. Two failed invokes send the event to the SQS transcribe dead-letter queue `transcribe-event-dead-letter`.
- Costs: a service event on the default bus. The rule has no standing fee.

**EventBridge application bus** (`job-outcome-event-bus`)

- Does: carries the finished-job event. The source is `bundesliga.localization`.
- Triggered by: the Step Functions publish states in the state machine `workflow`.
- Triggers: the fan-out rule `JobOutcomeFanoutRule`.
- Costs: one custom event per finished job, $1.00 per million in the example.

**Fan-out rule** `JobOutcomeFanoutRule` (EventBridge rule on `job-outcome-event-bus`)

- Does: matches every event from `bundesliga.localization`, whichever of the four names it is.
- Triggered by: the EventBridge application bus `job-outcome-event-bus`.
- Triggers: the SNS topic `job-outcome-fanout-topic`. Two failed publishes send the event to the SQS fan-out dead-letter queue `job-outcome-fanout-dead-letter`.
- Costs: no standing fee.

### Finished-job events

All four use the source `bundesliga.localization`. The detail carries version 1, the job id, the profile, the status, the source language, the reason, and the subtitle keys. A URL is not included, because it would expire in the queue.

**LocalizationJobCompleted**

- Does: says the six subtitle files were written.
- Triggered by: `PublishCompleted`, after `SaveCompleted`.
- Triggers: the EventBridge fan-out rule `JobOutcomeFanoutRule`, then the SNS topic `job-outcome-fanout-topic`, then the SQS consumer queue `job-outcome-inbox`.
- Costs: one custom event.

**LocalizationJobEmpty**

- Does: says the file had no speech. No subtitle files were written.
- Triggered by: `PublishEmpty`, after `SaveEmpty`.
- Triggers: the EventBridge fan-out rule `JobOutcomeFanoutRule`, then the SNS topic `job-outcome-fanout-topic`, then the SQS consumer queue `job-outcome-inbox`.
- Costs: one custom event.

**LocalizationJobNeedsReview**

- Does: says the language confidence was below 0.8. No subtitle files were written.
- Triggered by: `PublishNeedsReview`, after `SaveNeedsReview`.
- Triggers: the EventBridge fan-out rule `JobOutcomeFanoutRule`, then the SNS topic `job-outcome-fanout-topic`, then the SQS consumer queue `job-outcome-inbox`.
- Costs: one custom event.

**LocalizationJobFailed**

- Does: says the job stopped with an error. The reason is in the event.
- Triggered by: `PublishFailed`, after `SaveFailed`.
- Triggers: the EventBridge fan-out rule `JobOutcomeFanoutRule`, then the SNS topic `job-outcome-fanout-topic`, then the SQS consumer queue `job-outcome-inbox`.
- Costs: one custom event.

## Step Functions

One small job is about 13 transitions, $0.0003. The first 4,000 transitions each month are free, about 300 such jobs. A file over 2 GB adds the audio extract, about 15 transitions. Waiting is one transition. Starter starts the run. Status starts a later run for a language rerun or an accepted transcript.

**MarkRunning**

- Does: sets the job row to `running`.
- Triggered by: the start of the execution.
- Triggers: `PrepareMedia`.
- Costs: one state transition and one DynamoDB write.

**PrepareMedia**

- Does: chooses the path from the input.
- Triggered by: `MarkRunning`.
- Triggers: `BuildSubtitles` when a mixed transcript was accepted, `ExtractAudio` when the MP4 is over 2 GB, otherwise `Route`.
- Costs: one state transition.

**ExtractAudio**

- Does: asks MediaConvert for a mono MP3.
- Triggered by: `PrepareMedia`, for a file over 2 GB.
- Triggers: `UseExtractedAudio` on success. A failure goes to the failed outcome and `LocalizationJobFailed`.
- Costs: one state transition, plus MediaConvert per normalized minute. This state is skipped for a smaller file.

**UseExtractedAudio**

- Does: points the rest of the run at the MP3. The uploaded MP4 stays the file the site plays.
- Triggered by: a finished MediaConvert job.
- Triggers: `Route`.
- Costs: one state transition.

**Route, DetectedMode, and ForcedMode**

- Does: pick the Transcribe start from the profile. The start states are `StartHighlights`, `StartSpeakers`, `StartMulti`, `StartForcedPlain`, and `StartForcedSpeakers`. An unknown mode fails the execution.
- Triggered by: `PrepareMedia` or `UseExtractedAudio`.
- Triggers: one start-transcription state.
- Costs: one state transition per choice.

**Start transcription**

- Does: calls `StartTranscriptionJob`. A throttle is retried.
- Triggered by: the mode choice.
- Triggers: `WaitForTranscriptReady`. A start error goes to one lookup, which continues, waits, or fails.
- Costs: one state transition. The audio is billed by Transcribe, not by this state.

**WaitForTranscriptReady**

- Does: invokes token, then waits up to four hours.
- Triggered by: a transcription start, or a start error that found a job already running.
- Triggers: `BuildSubtitles` when the resume Lambda `transcribe-finished-callback`, or the status Lambda `status`, sends the token and Amazon Transcribe completed. A four-hour timeout causes one lookup. A failed transcription publishes `LocalizationJobFailed`.
- Costs: one state transition for the wait. The lookup is another.

**BuildSubtitles**

- Does: invokes the subtitle Lambda `write-translated-subtitles`.
- Triggered by: a completed transcript, an accepted mixed transcript, or a timeout that found a completed job.
- Triggers: the outcome that matches the function result.
- Costs: one state transition, plus the subtitle Lambda `write-translated-subtitles`.

**Outcome and the four saves**

- Does: writes `completed`, `empty`, `needs_review`, or `failed`, and only while the row is still `running`.
- Triggered by: the subtitle result, or an earlier failure path.
- Triggers: the matching publish state.
- Costs: one state transition and one DynamoDB write.

**The four publishes**

- Does: publishes one event, then ends the execution.
- Triggered by: the matching save.
- Triggers: `LocalizationJobCompleted`, `LocalizationJobEmpty`, `LocalizationJobNeedsReview`, or `LocalizationJobFailed` on the EventBridge application bus `job-outcome-event-bus`.
- Costs: one state transition, plus one custom event.

## Dead-letter queues

SQS bills the request that writes or reads a message. An empty queue has no standing fee. A message stays 14 days. A message here means delivery failed after the retries.

**Upload dead-letter queue**

- Does: holds an `Object Created` event that never reached the starter Lambda `start-workflow-on-upload`.
- Triggered by: the EventBridge upload rule `IngressCreated`, after two failed invokes.
- Triggers: the upload dead-letter alarm.
- Costs: SQS requests for that message. Nothing while the queue is empty.

**Transcribe dead-letter queue**

- Does: holds a `Transcribe Job State Change` that never woke the Step Functions state machine `workflow`. A common cause is the token not being stored yet by the token Lambda `store-transcribe-task-token`.
- Triggered by: the EventBridge transcript rule `TranscriptReady`, after two failed invokes.
- Triggers: the transcribe dead-letter alarm.
- Costs: SQS requests for that message.

**Fan-out dead-letter queue**

- Does: holds a finished-job event that never reached SNS. The subtitle files are already in the bucket.
- Triggered by: the EventBridge fan-out rule `JobOutcomeFanoutRule`, after two failed publishes.
- Triggers: the fan-out dead-letter alarm.
- Costs: SQS requests for that message.

**Inbox dead-letter queue**

- Does: holds a queue message the consumer received and failed five times.
- Triggered by: the SQS consumer queue `job-outcome-inbox`, after five receives.
- Triggers: the inbox dead-letter alarm.
- Costs: SQS requests for that message.

The SQS consumer queue `job-outcome-inbox` is the normal inbox. It keeps messages for 14 days. It is not alarmed, because a partner may not be reading it yet. After a successful publish the path is the EventBridge application bus `job-outcome-event-bus`, the fan-out rule `JobOutcomeFanoutRule`, the SNS topic `job-outcome-fanout-topic`, then that queue.

## Monitoring

**Alarm topic**

- Does: receives alarm and budget notices. Nothing is subscribed by email.
- Triggered by: the alarms below, and by the monthly budget.
- Triggers: nothing else in this stack.
- Costs: an SNS publish when an alarm or the budget fires. No standing recipient.

**Jobs completed, Jobs needing review, Jobs with no speech, Jobs failed**

- Does: counts how many times the workflow entered `SaveCompleted`, `SaveNeedsReview`, `SaveEmpty`, or `SaveFailed`. A stored failure counts here even when the execution itself succeeds. Those saves are what publish `LocalizationJobCompleted`, `LocalizationJobNeedsReview`, `LocalizationJobEmpty`, and `LocalizationJobFailed`.
- Triggered by: those save states being entered.
- Triggers: the job-failed alarm, for the failed count only, at one event.
- Costs: four custom metrics, summed over the dashboard time range.

**Executions started, succeeded, crashed, timed out**

- Does: counts workflow runs. Crashed means the execution stopped with an error. Timed out means the six-hour execution limit, not the four-hour transcript wait.
- Triggered by: Step Functions.
- Triggers: the workflow-failed alarm, for the crashed count only, at one event.
- Costs: Step Functions' own metrics. No extra product.

**Four dead-letter charts**

- Does: shows how many messages are waiting on each dead-letter queue. Zero means the event was delivered. A rise means a delivery failed after the retries.
- Triggered by: messages landing on those queues.
- Triggers: one alarm per queue when a message is visible.
- Costs: the SQS visible-message metric. The alarm fires on that count.

**Monthly budget**

- Does: watches account spend against $25.
- Triggered by: AWS billing.
- Triggers: the alarm topic when actual spend passes 80 percent, which is $20.
- Costs: the budget is a ceiling, not a fee for running the pipeline.

## Trade-offs

Each limit is there because the brief asks for subtitle files, or because the extra work would bill a monthly fee even when nobody uploads. The full notes are in [Trade-offs](trade-offs.md).

- Deploy is `cdk deploy` from a laptop. There is no CI pipeline.
- One region, and no VPC. A NAT gateway would cost money on days with no video.
- No queue in front of Transcribe. The account allows 250 batch jobs at once. The Transcribe job name is what stops a second run. A later control, not turned on, is Transcribe's own waiting line.
- The site polls every two seconds. A transcription takes minutes, so a socket would not change when the subtitles appear.
- Speakers stay anonymous: `spk_0` and so on. Interview allows 3, feature allows 6. Filling the ceiling marks the job saturated.
- Cue text goes through Translate only. Timestamps are copied. Volume leveling and burned-in captions stay off.
- Banners and lower-thirds stay in the picture. Rebuilding the graphic would mean a new video.
- A language score below 0.8 stops before translation and is stored as `LocalizationJobNeedsReview`. The site can force `en-US` or `de-DE`, or accept a mixed transcript. A person cannot yet correct one line and send it back.
- The transcript is a first draft. A short English word can come out as "DE", a name can be spelled the way it sounds, and a speaker label can stay on the previous voice. The tables are in [Known issues](trade-offs.md#known-issues).
- The files on hand are English, and one mixes in German. Every profile may be English, German, or both. Spanish is a subtitle file only.
- MP4 only, up to 5 GB, in one PUT. The same bytes, size, profile, and subtitle languages are one job. Files over 5 GB would need a multipart upload identified by CRC-64/NVME. That path is not built. In this case, for a multipart upload, S3 first calculates a **CRC64NVME checksum for each individual part** as it is uploaded. Once all parts are finished, S3 **concatenates the binary checksums** of those parts in order. It then runs the **CRC64NVME algorithm one final time** on that combined string of hashes. The result is appended with the total part count to create the final validation string, ensuring no data was corrupted during the entire upload process. **The Format:** The final string returned by S3 looks like `[Base64_Checksum]-[Number_of_Parts]`. For example: `h4B1v...=-4`.
- Anyone who can open the CloudFront hostname can request an upload URL. There is no login, no web application firewall, and no custom domain.
- The media buckets allow any origin to finish a request that already carries a valid 15-minute URL. The objects stay private.
- Other teams subscribe to the EventBridge application bus `job-outcome-event-bus` or the SQS consumer queue `job-outcome-inbox`. They do not read the DynamoDB job table, and they do not start Amazon Transcribe. A dubbed track or a rebuilt banner would start from `LocalizationJobCompleted`.
